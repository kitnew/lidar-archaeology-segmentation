\section{Overview of Conducted Experiments}

This chapter presents the quantitative and qualitative results of the conducted experiments. The experiments were treated not as an independent sequence of model runs, but as a set of controlled experimental groups. Each group was designed to assess the impact of a single methodological component, such as input data representation, label representation, loss function, sampling strategy, or model architecture. This structure allows us to distinguish general trends from the specific results of individual configurations. A detailed description of all configurations will not be provided due to their high variability; they follow directly from the methodology described above and adhere to a defined evaluation protocol.

Experiments were conducted separately for the datasets on Maya structures and Slovak terraces, as these two study areas differ in object morphology, terrain context, and annotation characteristics. The Maya dataset focuses primarily on compact archaeological structures, whereas the Slovak dataset contains linear objects similar to terraces. Therefore, the results are presented separately for both areas and only then compared at the level of methodological trends. A complete description of the characteristics of the available data is provided in Chapter 4.

Only experiments conducted on the latest consistent version of the workflow will be considered to ensure the objectivity of the subsequent comparison and to minimize the impact of possible methodological drift from minor changes. This will ensure a meaningful comparison of the tested components regardless of the input data domain.

\section{Reference and Best-Performing Configurations}
\subsection{Best-Performing Configuration for Maya Structures}

For the Maya dataset, the best-performing configuration was obtained with the following setup:
\begin{itemize}
    \item Model: DeepLab V3+ with an ImageNet-pretrained ResNet-101 backbone;
    \item Input representation: SPS visualization with radius = 10 m, n\_dir = 16, noise\_sup = 0, and z-score normalization;
    \item Label representation: soft mask with radius = 2 m;
    \item Loss function: Tanimoto with complement loss;
    \item Tile size: $128 \times 128$ pixels with a stride of 32 pixels.
\end{itemize}

This configuration is used as the reference result for the Maya structures because it achieved the strongest overall performance among the evaluated variants. To provide a meaningful comparison, it is contrasted with the older DeepLab V3 model trained without pretrained weights. This comparison should not be interpreted as an isolated evaluation of pretraining alone, since the models also differ architecturally. However, it remains useful as a representative comparison between the strongest final configuration and the earlier baseline, especially because the non-pretrained DeepLab V3 and DeepLab V3+ variants showed only minor differences in the preliminary experiments.

The pixel-wise results are summarized in Table~\ref{tab:maya_v3_v3+_metrics}. Only the metrics that provide useful information for this highly imbalanced segmentation problem are reported. Overall accuracy and background-dominated measures were omitted, since they can overestimate performance when the foreground class occupies only a small part of the raster. The results show that the DeepLab V3+ configuration improves all retained pixel-level indicators. The most important improvements are visible in foreground IoU, F1 score, and Matthews correlation coefficient, which indicates that the model provides a more balanced segmentation of the archaeological structures rather than merely preserving the dominant background class.

Since pixel-wise metrics do not fully describe the practical usefulness of the predictions in archaeological prospection, an object-wise evaluation was also performed. The results are shown in Table~\ref{tab:maya_v3_v3+_object_metrics}. From the object-level perspective, DeepLab V3+ detected 2253 ground-truth objects, compared with 1746 objects detected by DeepLab V3. Given the total number of 4084 reference objects, this corresponds to a substantially higher coverage of the available archaeological structures. At the same time, the average pixel hit rate per detected object is slightly lower for DeepLab V3+, and the number of false-positive predicted objects is higher. Therefore, the improvement of DeepLab V3+ should be interpreted primarily as an increase in detection completeness rather than as a reduction of all error types.

This behaviour is consistent with the practical objective of the task. In the context of archaeological candidate detection, missing a potential structure may be more problematic than producing additional candidates that can later be reviewed by an expert. The qualitative comparison in Figure~\ref{fig:maya_tp_fp_fn_comparison} supports this interpretation. Both models tend to fail in similar situations: small isolated structures with weak terrain expression are often missed, while natural terrain forms with morphology similar to anthropogenic structures may produce false positives. However, the DeepLab V3+ configuration identifies a larger portion of potential structures and therefore provides a more useful basis for subsequent expert-guided interpretation.

\subsection{Best-Performing Configuration for Slovak Terraces}

For the Slovak terrace dataset, the best-performing configuration was obtained with the following setup:
\begin{itemize}
    \item Model: DeepLab V3+ with a ResNet-101 backbone;
    \item Input representation: ANISO visualization;
    \item Label representation: soft mask with radius = 2 m;
    \item Loss function: BCE+Dice loss;
    \item Tile size: $512 \times 512$ pixels with a stride of 128 pixels.
\end{itemize}

This configuration is used as the reference result for the Slovak terrace dataset because it achieved the strongest overall performance among the evaluated variants. However, in contrast to the Maya structures, the interpretation of the Slovak results is less straightforward. The terrace task involves narrow, elongated, and partially discontinuous features represented by buffered polylines. Therefore, a prediction may correctly indicate the presence of a terrace complex while still obtaining relatively low pixel-wise overlap with the reference mask.

To keep the comparison consistent with the Maya results, the selected DeepLab V3+ configuration is compared with the same architecture using an ImageNet-pretrained backbone. The comparison shows a clear difference between the two variants. Although the pretrained model showed more stable behaviour during training, the final validation metrics favour the model trained from scratch. As shown in Table~\ref{tab:slovakia_v3_v3plus_metrics}, the non-pretrained DeepLab V3+ achieved higher balanced accuracy, true positive rate, F1 score, foreground IoU, average IoU, and Matthews correlation coefficient. The only retained pixel-level metric in which the pretrained model performed better is positive predictive value, indicating a more conservative prediction behaviour.

The object-wise evaluation in Table~\ref{tab:slovakia_v3plus_object_metrics} confirms the same general tendency, but also shows the limitations of the selected model. The non-pretrained DeepLab V3+ detected more ground-truth terrace objects and produced a substantially higher average hit rate per detected object. At the same time, it generated more predicted objects and a larger number of false positives. The ImageNet-pretrained model produced fewer false-positive objects and more true-positive predicted components, but it detected fewer ground-truth objects overall. This suggests that the pretrained model is more selective, whereas the non-pretrained model is more sensitive to terrace-like terrain patterns.

The qualitative inspection in Figure~\ref{fig:terraces_ladzany_sasovske_tp_fp_fn} supports this interpretation. The non-pretrained model often identifies the approximate location of terrace complexes, especially in areas where the terrain morphology is visually pronounced. However, it does not reliably separate individual terrace lines. Instead, it tends to merge parts of the terrace system into larger connected regions or to activate on neighbouring terrain forms with similar morphology. This behaviour increases recall but also produces a large number of false-positive predictions.

The detailed example in Figure~\ref{fig:terraces_ladzany_tp_fp_fn} illustrates the same limitation at a smaller scale. Several terrace segments are partially detected, but many annotated lines remain false negatives, while additional predictions appear in nearby areas without positive reference pixels. This indicates that the model learned a general representation of terrace-like relief, but did not achieve precise segmentation of individual terrace structures.

Overall, the Slovak terrace results should therefore be interpreted more cautiously than the Maya results. The selected configuration is the most useful among the tested variants because it provides the highest coverage of potential terrace areas and the strongest foreground-oriented metrics. Nevertheless, the high number of false positives and the merging of individual terraces show that the model output is not suitable as a final segmentation map. Its practical value is closer to a candidate layer for expert inspection, where the model can highlight possible terrace complexes but still requires manual verification and interpretation.

\section{Ablation Study}
\subsection{Effect of Input Representation}

Of the four input representations tested—namely DEM, RGB, RGDEM, and SPS—which were evaluated using identical hyperparameters and components, SPS demonstrated the best results. The evaluation metrics for each representation are shown in Table #. SPS demonstrates the highest pixel-level metrics and the most stable training performance among all other options. Moreover, it leads the others by more than 5%. In contrast, the RGB and RGDEM representations differ minimally from one another, although RGDEM achieved a slightly higher peak in IoU. Meanwhile, DEM demonstrates the worst results, likely due to insufficient gradient contrast.
